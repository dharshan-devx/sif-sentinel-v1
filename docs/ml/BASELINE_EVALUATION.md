### Data Leakage Assessment

> [!WARNING]
> **Near-duplicate templates across splits:** The dataset contains only 16 unique base templates, each repeated 40 times with an appended "Prototype record N." suffix. Since the TF-IDF vectorizer treats these suffixes as additional features, the train/test split contains semantically identical texts differentiated only by a numeric suffix. This constitutes **template-level data leakage** — the model has effectively memorized the templates.
>
> **This explains the perfect 100% metrics.** The metrics are NOT representative of real-world performance.

## NLP Pipeline

The full NLP analysis pipeline is located at `backend/app/services/nlp/analysis_pipeline.py`.

### Pipeline Steps

1. **Preprocessing** (`preprocessing.py`): Unicode NFKC normalization, smart-quote replacement, whitespace collapse, lowercase, regex sentence split `(?<=[.!?])\s+`.
2. **SIF Classification** (`sif_classifier.py` → `predictor.py`): TF-IDF vectorization + logistic regression `predict_proba`. Produces binary SIF/NON_SIF label and probability.
3. **Entity Extraction** (`entity_extractor.py`): Dictionary-based regex matching for Activities (14 categories), Hazards (15 categories), and Barriers (17 categories). Uses 5-token context windows for negation/verification detection.
4. **LSR Mapping** (`lsr_mapper.py`): Scores extracted entities against JSON-defined Life-Saving Rules using keyword, activity, hazard, and barrier signal matching. Minimum score threshold: 0.32.
5. **Evidence Extraction** (`evidence_extractor.py`): Sentence-level matching for extracted entity terms.
6. **Confidence Scoring** (`confidence.py`): Weighted linear combination (0.45*classifier + 0.25*entity + 0.20*rule + 0.10*evidence). Heuristic, NOT calibrated probability.
7. **Risk Calculation** (`risk_engine/calculator.py`): Multi-component deterministic risk score.
8. **Explanation Generation** (`analysis_pipeline._explain`): Template-based string concatenation.

## Known Limitations

1. **Synthetic Data Only:** The model is trained on 640 records generated from 16 text templates. It has never seen real-world incident reports.
2. **Template Data Leakage:** Train/test splits contain near-identical texts from the same templates, inflating evaluation metrics to 100%.
3. **Limited Vocabulary:** The TF-IDF vectorizer learned vocabulary only from 16 templates. Out-of-vocabulary terms (common in real reports) will not contribute to predictions.
4. **No Contextual Understanding:** TF-IDF is a bag-of-words model. It cannot understand sentence structure, negation scope, coreference, or semantic meaning.
5. **Dictionary Entity Extraction:** Entity extraction uses hardcoded keyword lists. Synonyms, misspellings, and domain jargon not in the lists are missed.
6. **Heuristic Confidence:** The overall confidence score is a non-calibrated linear combination, not a statistical probability.
7. **Primitive Sentence Segmentation:** Regex-based `(?<=[.!?])\s+` fails on abbreviations ("e.g.", "p.s.i.", "Dr.").
8. **No Lemmatization:** The preprocessor does not lemmatize, so "isolated" and "isolation" are treated as different tokens.
9. **Synchronous Execution:** The full NLP + LLM pipeline runs inline during HTTP request processing.

## Reproducibility

To reproduce the baseline from scratch:

```bash
# 1. Create and activate virtual environment
cd backend
python -m venv .venv
.venv\Scripts\activate    # Windows
# source .venv/bin/activate  # Linux/Mac

# 2. Install dependencies
pip install -e ".[dev]"

# 3. Retrain model (optional — artifacts already exist)
python ../ml/training/train_sif_model.py

# 4. Run all tests including AI regression tests
pytest tests/ -v

# 5. Run AI baseline tests only
pytest tests/test_ai_baseline.py -v
```

Random seed: `2026` (hardcoded in `train_sif_model.py`)
